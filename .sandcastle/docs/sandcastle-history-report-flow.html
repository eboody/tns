Sandcastle workflow / history-report generation

What the flow is actually doing

This is not one giant prompt over a folder of records. The flow first classifies document kinds, applies special handling rules per kind, launches bounded containerized agent work for each stage, and only allows downstream drafting when governed artifacts are complete enough to trust.

Core split agents do reasoning; artifacts carry state; governors decide whether the workflow may continue.
artifact-first document-class aware stage-bounded human-gated where doctrine matters

1. Inputs and source policy

inventory decides what kind of thing each file is
Hierarchy 1

Clinician intake notes

High-trust narrative source. Split into logical source units and preserve provenance line ranges.

Hierarchy 1

Questionnaires

Admitted as contemporaneous self-report; later tagged differently from clinician-note content.

Hierarchy 2

Referral materials / prior evaluations

Useful for rationale and prior findings, but not allowed to silently dominate the final narrative.

Hierarchy 3

Academic records

Admitted with OCR caution and later compressed into chronology/performance evidence rather than raw lists.

Excluded

Generated reports

Explicitly excluded from the working source set so past polished prose cannot masquerade as fresh evidence.

Special handling

Wrapper noise / empty markdown

Conversion notes, headings, scratch files, and empty artifacts are filtered before downstream work begins.

Governors

deterministic workflow checks
Admission governor

Include / exclude by document kind

Prevents generated reports and administrative noise from entering the evidence path.

Artifact completeness governor

Only advance when the stage wrote the expected structured outputs

Inventory, evidence, planning, and style stages all produce named artifacts under the run root.

Doctrine / HITL governor

Stop when clinician confirmation is required

Style profile and quote rules are intentionally provisional until confirmed by a human clinician.

Promotion governor

Generation and approval stay separate

Stable approved outputs should update only after explicit human promotion, not automatically after drafting.

2. Stage-bounded Sandcastle pipeline

current implemented slices are solid; downstream report assembly is planned next
bootstrap

Initialize stable case + run workspace

implemented

Creates the deterministic case/run roots, brief, privacy assumption, source registry seed, and Ralph scaffolding.

↓ classify candidate files and split source units
inventory

Apply document-class policy

implemented
  • infer document kind from path, content, and frontmatter
  • detect wrapper segments and logical source units
  • admit or exclude sources with an explicit hierarchy role
↓ launch bounded evidence extraction over admitted sources
evidence

Normalize segments and attributed atomic claims

implemented
  • tag each segment with source unit, lines, heading context, chronology cues, and conflict cues
  • distinguish self-report, collateral report, clinician note, prior-eval finding, and record fact
  • classify note fragments so follow-up prompts and diagnostic hypotheses do not flow downstream as ordinary facts
↓ classify the case and assign claim homes
planning

Resolve report schema and section ownership

implemented
  • infer child vs adult vs transition-age framing
  • select the honest section template for that lifecycle
  • assign each claim a primary section, salience, chronology bucket, and missingness mode
↓ separate truth-generation from voice-generation
style profile

Compile provisional clinician doctrine

implemented
  • derive voice rules, lexicon preferences, quote rules, and anti-style rules from exemplars
  • mark the result as requiring clinician confirmation before stable promotion
  • keep style guidance separate from factual evidence artifacts
↓ next governed slices
drafting

Render sections from approved artifacts, not raw source files

planned

Use claim-bank-like planning artifacts plus confirmed style doctrine to write clinician-native subsections without importing unsupported claims.

audit + provenance

Verify traceability and integration honesty

planned

Map final prose back to approved evidence and confirm that integration did not smuggle in extra interpretation.

promotion

Publish only on explicit human approval

planned

Stable approved outputs should move to the canonical latest artifacts only after a clinician says yes.

3. Durable artifacts each stage leaves behind

Run identity + privacy assumptions

Anchors the case id, run id, deliverable type, and initial workflow constraints.

01-inventory/

Source registry + inclusion log

Preserves why each source was admitted, excluded, or marked with caution.

02-evidence/

Segment annotations + atomic claims

4. Why this design exists

the class of problem it patches
Not: one omniscient model run that flattens intake notes, questionnaires, transcripts, referrals, and old reports into opaque prose.
Instead: explicit document taxonomy, explicit transformation rules, explicit stage outputs, and explicit human gates where doctrine or approval matters.
Effect: future report drafting becomes more inspectable, resumable, and auditable because each containerized task is bounded and governed.
The honest mental model: specialized agents work locally on typed artifacts; governors decide whether those artifacts are good enough to become the substrate for the next slice.
